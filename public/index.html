What Each Button Tests
Three real scenarios you might encounter
1
✅ Trusted Message
Correct signature + Real content = Accepted
The server confirms the message came from the real warehouse. The signature matches, so the inventory update goes through.
2
🚫 Wrong Password
Wrong signature = Rejected
The message was signed with a different secret. The server can tell it didn't come from a trusted source and blocks it immediately.
3
✏️ Tampered Message
Real signature + Modified content = Rejected
Someone intercepted the message and changed the quantity. Even one change breaks the signature, so the server knows it was tampered with.

How the Verification Works
Plain-English summary of the technical steps
How messages are signed A secret key is used to create a unique fingerprint of the message
How the server checks it It recalculates the fingerprint and compares — any difference means rejection
Is the secret safe? ✅ Never sent to the browser — server only
What prevents guessing? Comparison always takes the same time, so hackers can't guess by timing
